## 1. Vision

### Mission

Aegis Governance Runtime is a **governance middleware** that verifies agent decisions before they are allowed to modify memory, invoke tools, execute MCP operations, or change external state.

The goal is not to build another AI agent.

The goal is to build the **trust layer** that stands between autonomous agents and the systems they can affect.

### Problem Statement

Modern AI agents can:

- Read information
- Generate plans
- Call tools
- Mutate memory
- Execute workflows
- Perform autonomous actions

However, most systems cannot answer:

- Should this action have been allowed?
- Is the memory update valid?
- Does this decision violate a policy?
- Does this contradict existing knowledge?
- Can we prove why it happened?
- Can we detect later tampering?

Current agent architectures focus on **capability**.

Aegis focuses on **governance**.

### Core Philosophy

Aegis separates:

```
PROPOSAL
    from
AUTHORIZATION
```

The AI agent proposes.

Aegis decides.

### Architectural Principle

**Traditional architecture:**

```
User
  ↓
Agent
  ↓
Tool
  ↓
Database
```

**Aegis architecture:**

```
User
  ↓
Agent
  ↓
Aegis Governance Runtime  ←── Constitution + Policy + Memory Validator + Risk + Ledger
  ↓
Tool / Memory / MCP / Database
```

No state mutation occurs without governance review.

### Strategic Positioning

Aegis is intentionally **model-agnostic**.

Compatible with:

- OpenAI Agents
- Claude
- Gemini
- CrewAI
- LangGraph
- AutoGen
- MCP Servers
- Custom Agent Frameworks

The governance layer must remain **independent from the intelligence layer**.

### The Evolution

```
GhostProof          → "Here is the decision."
Runtime Sentinel    → "Here is the integrity."
Aegis Governance    → "Here is the decision, the evidence, the policy applied,
                        the record, and the proof that nobody manipulated the verification."
```

## 2. Core Concepts

### Proposal

A proposal is any operation generated by an agent that could affect state.

Examples:

- Store memory
- Update memory
- Delete memory
- Invoke tool
- Execute MCP action
- Write database record
- Modify configuration

### Governance Evaluation

Every proposal enters the governance pipeline:

```
Proposal
    ↓
Governance Evaluation
    ↓
Verdict
```

No proposal bypasses evaluation.

### Canonical Verdict Model

Aegis uses only **three verdicts**:

```java
enum Verdict {
    ALLOW,
    DENY,
    QUARANTINE
}
```

| Verdict | Meaning | Execution |
|---------|---------|-----------|
| `ALLOW` | Proposal satisfies all policies | Execution continues |
| `DENY` | Proposal violates one or more rules | Execution stops |
| `QUARANTINE` | Ambiguity, low confidence, unresolved conflict, or elevated risk | Isolated pending review |

### Reason Codes

```java
enum ReasonCode {
    NONE,
    DUPLICATE,
    CONTRADICTION,
    MISSING_SOURCE,
    LOW_CONFIDENCE,
    HIGH_RISK_TOOL,
    POLICY_VIOLATION,
    MEMORY_TAMPERING,
    INVALID_SCHEMA,
    PROVENANCE_UNVERIFIED,
    BUDGET_EXCEEDED,
    CONSTITUTION_COMPROMISED,
    QUARANTINE_EXPIRED
}
```

Examples:

```json
{
  "verdict": "DENY",
  "reason_code": "DUPLICATE"
}
```

```json
{
  "verdict": "QUARANTINE",
  "reason_code": "LOW_CONFIDENCE"
}
```

### Quarantine Lifecycle

QUARANTINE is not a terminal state. It is a **governance queue**:

```
QUARANTINE
    ↓
UNDER_REVIEW
    ↓
┌───────────┼───────────┐
│           │           │
▼           ▼           ▼
PROMOTE     DENY       EXPIRE
```

```java
enum QuarantineState {
    PENDING,
    UNDER_REVIEW,
    PROMOTED,
    DENIED,
    EXPIRED
}
```

- **TTL:** 24 hours (configurable)
- **Auto-expiry:** → `DENY` with `QUARANTINE_EXPIRED`
- **Review:** Human or Constitution Council (Mnemosyne integration)
- **Metrics:** Quarantine rate, promotion rate, average review time

### Constitutional Governance

A Constitution is a **deterministic** set of rules.

Unlike prompts, constitutional rules are **executable and testable**.

Examples:

- `NO_DUPLICATE`
- `NO_CONTRADICTION`
- `SOURCE_REQUIRED`
- `CONFIDENCE_THRESHOLD`
- `NO_MEMORY_TAMPERING`
- `NO_POLICY_BYPASS`
- `PROVENANCE_REQUIRED`

### Constitution Signing

The constitution is the **trust anchor**. If compromised, all governance is compromised.

```
charter_v1.yaml
charter_v1.sha256
charter_v1.sig  (Ed25519)
```

At startup:

```
Verify Signature
    ├── PASS → Start Runtime
    └── FAIL → FAIL CLOSED (CONSTITUTION_COMPROMISED)
```

Every audit event includes:

```json
{
  "constitution_version": "v1.0.0",
  "constitution_hash": "sha256:abc123..."
}
```

### Evaluation Pipeline (Deterministic Order)

```
Stage 1: Schema Validation
         ├── INVALID_SCHEMA → DENY
         └── MISSING_SOURCE → DENY

Stage 2: Constitution Validation
         ├── DUPLICATE → DENY
         └── POLICY_VIOLATION → DENY

Stage 3: Conflict Analysis
         ├── CONTRADICTION → QUARANTINE
         └── SUPERSEDED → ALLOW (with supersedes chain)

Stage 4: Risk Analysis
         ├── LOW_CONFIDENCE → QUARANTINE
         └── HIGH_RISK_TOOL → DENY

Stage 5: Verdict Resolution
         └── Final Verdict + ReasonCode

Stage 6: Ledger Recording
         └── Event persisted with hash chain
```

This order is **non-negotiable**. It guarantees determinism.

## 3. Canonical Data Model

### Memory Fact (Structured Knowledge)

Memory is represented as **structured knowledge**, not natural language.

```json
{
  "subject": "USER",
  "predicate": "COUNTRY_OF_RESIDENCE",
  "value": "PERU",
  "confidence": 0.95,
  "source": "conversation",
  "valid_from": "2026-11-24T00:00:00Z",
  "valid_to": null
}
```

| Field | Purpose |
|-------|---------|
| `subject` | Entity being described |
| `predicate` | Fact category |
| `value` | Actual fact value |
| `confidence` | Confidence score (0.0–1.0) |
| `source` | Origin of information |
| `valid_from` | Activation timestamp |
| `valid_to` | Expiration timestamp (null = active) |

### Contradiction Detection

Current fact:

```json
{
  "subject": "USER",
  "predicate": "COUNTRY_OF_RESIDENCE",
  "value": "PERU"
}
```

New fact:

```json
{
  "subject": "USER",
  "predicate": "COUNTRY_OF_RESIDENCE",
  "value": "CANADA"
}
```

Result:

```json
{
  "verdict": "QUARANTINE",
  "reason_code": "CONTRADICTION"
}
```

Contradiction is **mathematical**, not linguistic:

```
Same subject + Same predicate + Different value + Both active = CONTRADICTION
```

### Supersession (Temporal Re-evaluation)

When a fact changes legitimately:

```json
{
  "verdict": "ALLOW",
  "reason_code": "NONE",
  "supersedes": "evt-041"
}
```

The old fact gets `valid_to` set. The new fact becomes active.

Historical decisions based on the old fact are flagged for `REVIEW`.

### Canonical Audit Event

Every governance decision becomes an **immutable audit event**:

```json
{
  "event_id": "evt-001",
  "timestamp_utc": "2026-11-24T10:00:00Z",
  "actor": "agent-01",
  "action": "MEMORY_WRITE",
  "verdict": "ALLOW",
  "reason_code": "NONE",
  "constitution_version": "v1.0.0",
  "constitution_hash": "sha256:abc123...",
  "prev_hash": "abc123...",
  "payload_hash": "xyz456...",
  "event_hash": "def789..."
}
```

### Hash Chain Model

Two distinct hashes serve different purposes:

**payload_hash** — protects the content:

```
payload_hash = SHA256(CanonicalJson(payload))
```

**event_hash** — protects the chain of evidence:

```
event_hash = SHA256(CanonicalJson(event_metadata) + prev_hash + payload_hash)
```

Visual:

```
Payload
    ↓
payload_hash
    +
Event Metadata
    +
prev_hash
    ↓
event_hash
```

### Canonical Serialization

Before hashing:

1. Sort fields alphabetically
2. Remove formatting variance
3. Normalize values (timestamps to UTC ISO-8601, etc.)
4. Generate canonical JSON (no whitespace, sorted keys)
5. Compute SHA-256

The same event must **always** generate the same hash.

### Idempotency

Every proposal carries an `idempotency_key`:

```json
{
  "idempotency_key": "req-20261125-001",
  "action_type": "memory.write",
  "payload": { ... }
}
```

If the same key is seen again:

```json
{
  "verdict": "DENY",
  "reason_code": "DUPLICATE"
}
```

This prevents double-execution on retries.

### Layer Model

```
┌──────────────────────────────────────────────────────────────┐
│                      PROPOSAL LAYER                          │
│  Claude · GPT · Gemini · CrewAI · LangGraph · AutoGen · MCP │
└──────────────────────────────┬───────────────────────────────┘
                               │ Proposal
                               ▼
┌──────────────────────────────────────────────────────────────┐
│                  AEGIS GOVERNANCE RUNTIME                    │
│                                                              │
│  ┌─────────────┐  ┌──────────────┐  ┌───────────────────┐  │
│  │ Constitution│  │    Memory    │  │     Policy        │  │
│  │   Engine    │  │  Validator   │  │     Engine        │  │
│  └──────┬──────┘  └──────┬───────┘  └────────┬──────────┘  │
│         │                │                    │              │
│         ▼                ▼                    ▼              │
│  ┌──────────────────────────────────────────────────────┐   │
│  │              EVALUATION PIPELINE                      │   │
│  │  Schema → Constitution → Conflict → Risk → Verdict   │   │
│  └──────────────────────────┬───────────────────────────┘   │
│                             │                                │
│                    ┌────────┴────────┐                       │
│                    ▼                 ▼                       │
│              VERDICT:          VERDICT:                      │
│               ALLOW        DENY / QUARANTINE                 │
│                    │                 │                       │
│                    ▼                 │ (fail-closed)          │
│  ┌─────────────┐                      │                       │
│  │ Execution   │                      │                       │
│  │   Guard     │                      │                       │
│  │ (timeout +  │                      │                       │
│  │  budget +   │                      │                       │
│  │  idempot.) │                      │                       │
│  └──────┬──────┘                      │                       │
│         │                             │                       │
│         └──────────┬──────────────────┘                       │
│                    ▼                                          │
│  ┌──────────────────────────────────────────────────────┐   │
│  │              AEGIS LEDGER                            │   │
│  │  payload_hash · event_hash · prev_hash · chain       │   │
│  └──────────────────────────────────────────────────────┘   │
└──────────────────────────────┬───────────────────────────────┘
                               │ Receipt (event_hash)
                               ▼
┌──────────────────────────────────────────────────────────────┐
│                     EXECUTION LAYER                          │
│  MCP Servers · Databases · File Systems · APIs · Tools      │
└──────────────────────────────────────────────────────────────┘
```

### Proposal Layer

Produces proposals. **Only proposals. Never direct execution.**

### Governance Runtime Components

**Constitution Engine** — Evaluates constitutional rules deterministically.

**Memory Validator** — Ensures memory consistency: schema, validity, contradictions, confidence, source.

**Policy Engine** — Evaluates permissions: can call tool? can write memory? can modify state?

**Risk Engine** — Assigns operational risk: `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`.

**Evidence Engine** — Generates decision evidence, reason codes, evaluation reports.

**Ledger Engine** — Persists immutable governance evidence with hash chains and tamper detection.

### Execution Guard

- **Timeout:** Configurable per action type
- **Budget:** Max iterations/steps per session
- **Idempotency:** Duplicate request detection
- **Circuit Breaker:** `CLOSED → OPEN → HALF_OPEN → CLOSED`
- **Compensation:** Saga pattern for multi-step actions

### Integrity Verification

At runtime:

```
Verify Hash Chain
    ├── All valid → INTEGRITY OK
    └── Any broken → INTEGRITY BROKEN
```

## 6. Future Research Directions

These are **not V1**. They are the research agenda that makes Aegis a platform.

### 6.1 Cross-Agent Trust Propagation (V3)

When an agent is compromised, all memories it produced degrade across the network.

```
Agent X produces Memory M1 → ALLOW (confidence 1.0)
Agent X is compromised
→ M1 confidence drops to 0.2
→ All decisions based on M1 → re-evaluated
→ QUARANTINE cascade
```

Trust becomes a **network property**, not an individual one.

### 6.2 Temporal Re-evaluation (V2)

Verdicts are valid **under the knowledge available at evaluation time**.

```
Day 1:  "User lives in Peru" → ALLOW
Day 30: New evidence: "User moved to Canada"
→ Retroactive re-evaluation
→ Original memory → SUPERSEDED
→ Decisions based on it → REVIEW
```

### 6.3 Reverse Governance / Agent Appeals (V2)

Agents can **appeal a DENY** with new evidence.

```
DENY (MISSING_SOURCE)
    ↓
Agent presents new evidence
    ↓
Re-evaluation
    ↓
PROMOTE if evidence is valid
```

Governance becomes **bidirectional**, not authoritarian.

### 6.4 Zero-Knowledge Audit Proofs (V3)

Prove a decision was correct **without revealing the payload**.

```
Agent processes medical data → ALLOW
Auditor asks: "Why was this allowed?"
Aegis responds: ZK-proof (no data revealed)
```

### 6.5 Governance Federation (V4)

Multiple Aegis instances **cross-verify** each other's ledgers.

```
Aegis-Instance-1 → Ledger hash
Aegis-Instance-2 → Ledger hash
Comparison → Consensus
Divergence → INTEGRITY BREACH
```

### 6.6 Merkle Checkpoints (V3)

Scalable verification without scanning the entire chain.

```
Checkpoint every 1000 events
Verify: checkpoint + last N events (O(log n))
```

### 6.7 Adaptive Constitution (V5)

Constitution evolves based on governance outcomes.

**Warning:** This conflicts with "Deterministic over Probabilistic." Requires solving "who governs the governor?" first.

### 6.8 Agent Behavioral Fingerprinting (V3)

Each agent has a behavioral fingerprint. Deviations trigger QUARANTINE.

```
Agent normally: 95% ALLOW, 5% DENY
Today: 40% ALLOW, 60% DENY
→ Deviation detected → QUARANTINE
```

## 8. Design Principles

1. **Deterministic over Probabilistic** — Same input + same constitution = same verdict, always.
2. **Governance over Autonomy** — No agent action without review.
3. **Evidence over Trust** — Every decision produces verifiable proof.
4. **Verification over Assumption** — "Trust me" becomes "Verify me."
5. **Structured Facts over Free Text** — Mathematics, not linguistics.
6. **Fail-Closed over Fail-Open** — When in doubt, DENY.
7. **Model-Agnostic over Vendor-Locked** — Works with any agent framework.
8. **V1 Boring over V3 Ambitious** — Prove governance first. Everything else later.

## 9. Threat Model

Every governance system is a target. Aegis must anticipate attacks on itself.

### Threat 01: Malicious Agent

**Description:** An agent deliberately proposes harmful actions or false memories.

**Detection:** Behavioral fingerprinting (V3), anomaly detection on proposal patterns.

**Mitigation:** Constitution rules (NO_DUPLICATE, NO_CONTRADICTION), Risk Engine, QUARANTINE.

**Verdict:** `DENY` or `QUARANTINE` depending on severity.

### Threat 02: Prompt Injection

**Description:** External input manipulates the agent into proposing unauthorized actions.

**Detection:** Constitution rules on provenance, source verification.

**Mitigation:** `PROVENANCE_REQUIRED`, `SOURCE_REQUIRED`, Execution Guard.

**Verdict:** `DENY · PROVENANCE_UNVERIFIED`.

### Threat 03: Constitution Tampering

**Description:** An attacker modifies `charter_v1.yaml` to weaken governance.

**Detection:** Ed25519 signature verification at startup and on reload.

**Mitigation:** Fail-closed on signature mismatch. Constitution hash embedded in every audit event.

**Verdict:** `FAIL CLOSED · CONSTITUTION_COMPROMISED` — entire runtime halts.

### Threat 04: Ledger Manipulation

**Description:** An attacker alters, deletes, or reorders audit events.

**Detection:** Hash chain verification (`prev_hash → event_hash`), Merkle checkpoints (V3).

**Mitigation:** Append-only ledger, chain verification on every read.

**Verdict:** `INTEGRITY BROKEN` — alert + freeze.

### Threat 05: Replay Attack

**Description:** An attacker re-submits a previously allowed proposal.

**Detection:** `idempotency_key` uniqueness check.

**Mitigation:** Ledger rejects duplicate keys.

**Verdict:** `DENY · DUPLICATE`.

### Threat 06: Duplicate Request (Retry Storm)

**Description:** An agent retries a proposal after timeout, creating duplicates.

**Detection:** Idempotency key + circuit breaker.

**Mitigation:** Circuit breaker opens after N failures, HALF_OPEN probes.

**Verdict:** `DENY · DUPLICATE` or `QUARANTINE · BUDGET_EXCEEDED`.

### Threat 07: Quarantine Escape

**Description:** A quarantined proposal is accidentally promoted without review.

**Detection:** Quarantine state machine enforcement.

**Mitigation:** `PROMOTE` requires explicit review action (human or Mnemosyne Council).

**Verdict:** `DENY · POLICY_VIOLATION` if bypass attempted.
